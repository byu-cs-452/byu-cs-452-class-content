Window Functions — Wednesday 9/23

Monday we used recursion to walk a hierarchy. Today we learn the other tool that saves you from writing three nested subqueries: window functions. A window function looks at a set of rows related to the current row, and still returns one row of output per input row.

1. The idea

GROUP BY collapses rows. A window function does not. It keeps every row and adds a column computed from a "window" of nearby rows.

SELECT region, SUM(amount)               FROM sales GROUP BY region;  -- 2 rows out
SELECT region, SUM(amount) OVER (PARTITION BY region) FROM sales;      -- 12 rows out

Reach for a window function whenever a question contains: rank, top N per group, running total, compared to the previous row, moving average, or percent of total.

2. The syntax

function_name(args) OVER (
    PARTITION BY expr   -- optional: start over for each group (like GROUP BY, but no collapsing)
    ORDER BY expr       -- optional: order rows inside the partition
    frame_clause        -- optional: which rows around the current one count
)

The frame clause is ROWS or RANGE plus bounds, for example:

ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW   -- everything up to here (running total)
ROWS BETWEEN 6 PRECEDING AND CURRENT ROW           -- a 7-row moving window
ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING           -- neighbors on both sides

If you use the same window more than once, name it instead of repeating it:

SELECT rep, amount,
       RANK()      OVER w AS rnk,
       SUM(amount) OVER w AS running_total
FROM sales
WINDOW w AS (PARTITION BY region ORDER BY sale_date);

3. Every MySQL window function

Ranking and distribution

FunctionWhat it gives you
ROW_NUMBER()1, 2, 3, ... with no ties. Ties are broken arbitrarily unless you order by something unique.
RANK()Ties share a rank, and the next rank skips: 1, 1, 3.
DENSE_RANK()Ties share a rank, with no gap: 1, 1, 2. This is the one for "top 3 salaries".
PERCENT_RANK()Relative rank from 0 to 1, computed as (rank - 1) / (rows - 1).
CUME_DIST()Fraction of partition rows at or below this row's value.
NTILE(n)Splits the partition into n buckets and returns this row's bucket. Quartiles are NTILE(4).

Looking at other rows

FunctionWhat it gives you
LAG(expr, n, default)The value n rows back (default n = 1). Use it for day-over-day change.
LEAD(expr, n, default)The value n rows forward. Use it for "what happened next".
FIRST_VALUE(expr)First value in the frame.
LAST_VALUE(expr)Last value in the frame. Watch the frame: see the gotchas below.
NTH_VALUE(expr, n)The nth value in the frame, or NULL if the frame is shorter than n.

Aggregates used as window functions. Add OVER (...) to the aggregates you already know: SUM, AVG, COUNT, MIN, MAX, the statistical ones (STDDEV_POP, STDDEV_SAMP, VAR_POP, VAR_SAMP), the bit functions (BIT_AND, BIT_OR, BIT_XOR), and the JSON aggregates (JSON_ARRAYAGG, JSON_OBJECTAGG). Note that GROUP_CONCAT is not allowed as a window function.

A few restrictions worth knowing: in LAG, LEAD, NTH_VALUE, and NTILE, the count must be a literal number, not a column or an expression. IGNORE NULLS parses but is not supported.

Example 1 — three ways to number rows. The East region has two sales of 1500 and two of 600, so the differences show up clearly.

SELECT region, rep, amount,
       RANK()       OVER (PARTITION BY region ORDER BY amount DESC) AS rnk,
       DENSE_RANK() OVER (PARTITION BY region ORDER BY amount DESC) AS dense_rnk,
       ROW_NUMBER() OVER (PARTITION BY region ORDER BY amount DESC) AS row_num
FROM sales
ORDER BY region, amount DESC;

The East rows come back like this. Watch what each column does with the ties:

regionrepamountrnkdense_rnkrow_num

EastCasey750323
EastDevon600434
EastFinley600435

Example 2 — running total and day-over-day change.

SELECT sale_date, region, amount,
       SUM(amount) OVER (PARTITION BY region ORDER BY sale_date, id) AS running_total,
       LAG(amount) OVER (PARTITION BY region ORDER BY sale_date, id) AS prev_amount,
       amount - LAG(amount) OVER (PARTITION BY region ORDER BY sale_date, id) AS change
FROM sales
ORDER BY region, sale_date, id;

The first row of each region has a NULL prev_amount, because there is nothing before it. Use LAG(amount, 1, 0) if you want a zero instead.

5. Gotchas

  • You cannot use a window function in WHERE or HAVING. Window functions run after those clauses. Compute the value in a subquery or CTE, then filter outside it. This is the pattern behind nearly every "top N per group" problem: 
    WITH ranked AS (
    SELECT rep, region, amount,
           DENSE_RANK() OVER (PARTITION BY region ORDER BY amount DESC) AS rnk
    FROM sales
)
SELECT * FROM ranked WHERE rnk <= 3;
  • The default frame is not what you expect. With an ORDER BY and no frame clause, the frame is RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW, and RANGE treats tied rows as one unit. Two sales on the same date jump the running total together. Order by a tiebreaker (as above, sale_date, id) or say ROWS explicitly.
  • LAST_VALUE looks broken by default, because the frame ends at the current row, so the "last value" is the current row. You usually want ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING.
  • No ORDER BY in the OVER clause means every row in the partition is a peer. That is right for a partition total, and wrong for a running total.
  • ROW_NUMBER with an unstable sort gives different answers on different runs. Order by something unique when it matters.

6. Practice

These four are all free on LeetCode. Start with the first.

  1. 1204. Last Person to Fit in the Bus (medium): you solved this Monday with a recursive CTE. Now do it with one SUM() OVER (ORDER BY turn). Compare the two solutions, and notice how much shorter this one is.
  2. 180. Consecutive Numbers (medium): LAG and LEAD turn this into one comparison.
  3. 1321. Restaurant Growth (medium): a 7-day moving average, which is a frame clause with 6 PRECEDING. Careful: sum by day first, before you take the moving average.
  4. 185. Department Top Three Salaries (hard): the classic. Read the problem statement closely on what "top three" means when salaries tie, and pick your ranking function to match. This is the gotcha above, in exam form.
