1. The data

Open the table here (you can fork it and run queries in your browser): https://onecompiler.com/mysql/453wx95wm

CREATE TABLE employees (
    id         INT PRIMARY KEY,
    first_name VARCHAR(50),
    last_name  VARCHAR(50),
    manager_id INT NULL   -- NULL = top of the tree
);

INSERT INTO employees (id, first_name, last_name, manager_id) VALUES
    (1, 'Avery',   'Stone',    NULL),  -- CEO
    (2, 'Blake',   'Rivera',   1),
    (3, 'Casey',   'Nguyen',   1),
    (4, 'Devon',   'Okafor',   2),
    (5, 'Emerson', 'Lindqvist',2),
    (6, 'Finley',  'Marsh',    3),
    (7, 'Gray',    'Ito',      6);

Drawn as a tree (we'll build this in Figma in class):

Avery (1)
├── Blake (2)
│   ├── Devon (4)
│   └── Emerson (5)
└── Casey (3)
    └── Finley (6)
        └── Gray (7)

Key idea: Each row points to its parent through manager_id. That is a self-referencing table. One self-join gets you one level down. A recursive CTE follows the pointers as many levels as needed.

2. Anatomy of a recursive CTE

WITH RECURSIVE cte_name AS (
    -- 1. ANCHOR: the starting row(s). Runs once.
    SELECT ...
    UNION ALL
    -- 2. RECURSIVE STEP: joins back to cte_name.
    --    Runs over and over on the rows from the previous pass
    --    and stops when a pass returns no new rows.
    SELECT ... FROM some_table JOIN cte_name ON ...
)
SELECT * FROM cte_name;

Simplest possible example, counting 1 to 10:

WITH RECURSIVE nums AS (
    SELECT 1 AS n
    UNION ALL
    SELECT n + 1 FROM nums WHERE n < 10   -- the WHERE is the stopping condition
)
SELECT n FROM nums;

3. Walking the tree

A. Walk down: the whole org chart, with depth and path.

WITH RECURSIVE org AS (
    SELECT id, first_name, manager_id,
           0 AS depth,
           CAST(first_name AS CHAR(200)) AS path
    FROM employees
    WHERE manager_id IS NULL                 -- anchor: the CEO
    UNION ALL
    SELECT e.id, e.first_name, e.manager_id,
           o.depth + 1,
           CONCAT(o.path, ' > ', e.first_name)
    FROM employees e
    JOIN org o ON e.manager_id = o.id        -- children of the last level
)
SELECT * FROM org ORDER BY path;

MySQL gotcha: The anchor row sets the column types. Without the CAST(... AS CHAR(200)), path is only as wide as "Avery", and longer paths fail with a "Data too long" error.

B. Walk up: Gray's chain of command.

WITH RECURSIVE chain AS (
    SELECT id, first_name, manager_id, 0 AS steps
    FROM employees
    WHERE id = 7                             -- anchor: Gray
    UNION ALL
    SELECT m.id, m.first_name, m.manager_id, c.steps + 1
    FROM employees m
    JOIN chain c ON m.id = c.manager_id      -- move to my manager
)
SELECT * FROM chain;

Compare A and B. Walking up or down only changes which side of the join condition you are on.

Safety note: If the data has a cycle (A manages B, and B manages A), the recursion never stops. MySQL stops it at cte_max_recursion_depth (default 1000). You can also add your own guard, such as WHERE depth < 20.
