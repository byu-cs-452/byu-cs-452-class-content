MapReduce, step by step

Counting words in a book is easy on one machine. Counting words in the whole web is not. MapReduce splits one huge job into many small ones, runs them on many machines at once, and then combines the answers. Every MapReduce job has the same four moves:

Split→Map: emit (key, value)→Shuffle: same key, same machine→Reduce: combine each key

      Master, workers, local disks and failures

      Google's 2004 MapReduce paper (and Hadoop, built from it) adds the parts a real cluster needs: a distributed file system, a master that tracks every task, sorting and spilling to disk, a combiner, and re-running work when a machine dies.

        The same four moves in Spark

        # Split: textFile reads the file in partitions, one per machine
lines = sc.textFile("bookOfMormon.txt")
# Map: one (word, 1) pair per word
pairs = lines.flatMap(lambda line: line.lower().split()).map(lambda w: (w, 1))
# Shuffle + Reduce: reduceByKey combines on each machine first, then shuffles and sums
counts = pairs.reduceByKey(lambda a, b: a + b)
counts.sortBy(lambda t: t[1], False).take(10)
