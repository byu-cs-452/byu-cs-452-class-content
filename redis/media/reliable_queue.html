Reliable Queues: claim, work, acknowledge

With LPOP, a job leaves Redis the moment a worker takes it. If that worker crashes, the job is gone: nobody has it and nobody will ever answer. A reliable queue never lets a job be "in the air." LMOVE moves it from the queue to a processing list in one atomic step. The worker removes it only after the result is saved. A separate restorer process watches the processing list and puts abandoned jobs back in line.

    # worker: claim -> work -> save -> acknowledge
job = r.blmove("jobs:queue", "jobs:processing",
               5, "LEFT", "RIGHT")      # atomic
r.hset("jobs:claims", job_id,
       json.dumps({"worker": me, "at": time.time()}))
r.hincrby("jobs:attempts", job_id, 1)

result = do_the_work(job)               # call heartbeat()
                                        # if it's slow
r.set(f"result:{job_id}", result)       # save FIRST
with r.pipeline() as p:                 # then ack
    p.lrem("jobs:processing", 1, job)
    p.hdel("jobs:claims", job_id)
    p.hdel("jobs:attempts", job_id)
    p.execute()
    
    
    
    
    

    # restorer: every few seconds
for job in r.lrange("jobs:processing", 0, -1):
    claim = r.hget("jobs:claims", id_of(job))
    if claim is None:          # died before HSET:
        r.hsetnx(...now...)    # start the clock
    elif now - claim["at"] > LEASE_SECONDS:
        requeue(job)           # Lua script below

-- requeue, run atomically inside Redis
if redis.call('LREM', processing, 1, job) == 0
  then return 0 end            -- already acked
redis.call('HDEL', claims, id)
if attempts >= MAX then
  redis.call('RPUSH', dead, job)   -- give up
else
  redis.call('LPUSH', queue, job)  -- front of line
end
    
    
    
  
    
  
    The order matters: save the result, then acknowledge. If the worker dies between the two, the job runs again, which is fine because writing result:<id> twice gives the same answer. The other order could acknowledge a job whose result was never saved. This gives at-least-once delivery: every job is finished, and a few might be done twice. That's the guarantee Sidekiq, Celery and Amazon SQS give too.

    LREM + HDEL (acknowledge)XACK jobs workers <id>
    
        
    Restorer: LRANGE jobs:processing and check each claim's ageXPENDING jobs workers shows idle time and delivery count
    
        
    Restorer: requeue an abandoned jobXAUTOCLAIM jobs workers w2 10000 0 hands jobs idle more than 10 s to another worker
    
        
    jobs:attempts and jobs:deadDelivery count from XPENDING; past a limit, copy the job to a dead-letter stream and XACK it
