Polling vs. Notifications

Step through what happens inside the Redis project: the web front door turns an image into a JSON blob, a worker classifies it, and the answer comes back through a Redis key. Then see why the original design can't add workers, why polling wastes effort, and what changes when Redis notifies instead.

How the project works today

One request, one worker. Every arrow is a real Redis command from run_web_server.py or run_model_server.py. Both programs poll: they ask, sleep 0.25 s, and ask again.

Animation 2a · Problem 1

Why a second worker breaks things

LRANGE only reads the list, and LTRIM removes items later by position. Between those two commands another worker can read the same items, and new items can slide into the positions being trimmed.

Animation 2b · Problem 2

The cost of polling

Every waiting request asks Redis "is it done yet?" four times a second. Almost every answer is "no." Count how many questions it takes to get four answers.

Animation 3 · The improved design

Notifications for the front door, atomic pops for the workers

The web front door opens a connection and subscribes to its result key before pushing work. Redis sends exactly one message, the moment the worker writes the key. Workers switch to a pop that removes items as it reads them, so each item goes to exactly one worker. (Workers still check the queue on a timer; we leave that alone today.)

4 · Scale

10s, 100s, 1,000s, 1,000,000s of requests per second

Same image classifier, two architectures. Original: polling front door, one worker (a second one causes duplicate and lost work). Updated: notifications to the front door, atomic pop so you can run as many workers as the load needs.

Which node owns which key? That's consistent hashing, our next video.

Rough model: one CPU worker classifies about 16 images/s (a batch of 32 in ~2 s); polling every 0.25 s; one Redis node handles on the order of 100,000+ simple commands/s. Real numbers depend on hardware, but the shape holds: the original design is capped at one worker and its polling grows with the backlog.
