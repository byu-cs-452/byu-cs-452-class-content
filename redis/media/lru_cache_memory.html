    What real Python did (CPython 3.13, measured with id())

    • Nothing slides around. A node keeps the same address its whole life. Moving it to the front only rewires four or five pointers.
    • Quiet program: a node is freed the instant nothing points to it, and Python's allocator hands out the most recently freed block first. The new node landed at the exact address of the node it replaced 90% of the time (5 runs, about 250 evictions each).
    • Busy program: when other same-size objects were created and kept in between, they took the freed spot first. Reuse dropped to 0%, and the cache wandered over about 250 different addresses. Even the node's own data can do this: with __slots__, the value string was the same size as the node, and the two swapped places on every eviction.
    • Reference cycle: a node stuck in a cycle isn't freed until the garbage collector runs. In one run the first collection came at request 1,157, after 481 evictions. Until then only 11% of new nodes reused an old address; right after it, 100% did.
