# Building with agents, learning on paper (now through the Data Pipeline)

*[Page created using Claude by Professor Reynolds]*

From now until the final project, the class is trying an experiment in **how to learn**, and Professor
Reynolds is taking part in it alongside you.

## An opportunity

Each class is followed by a substantial project. There usually isn't time to hand-code all of them, or to
learn everything there is to know about each technology. So we have an opportunity to build with an **AI
coding agent** (see [Getting an AI coding agent](agent_options.md)). Monday's class (10/12) is set aside for
getting set up.

The hope isn't just to finish projects faster. It's that you can **learn more than you would have by hand**,
at two levels:

- **How it works, at a low level.** The specific command, setting or API call that makes something work,
  and why it doesn't work without it.
- **Why it's built that way, at a high level.** The architecture choices, their tradeoffs, and when you
  might choose something else.

An agent can build a project you don't understand. It can also be one of the most patient tutors you've ever
had. Some things to try: ask it *why*, ask it to explain what it just did, ask what would break if a line
were removed, ask it to quiz you, or ask it to go one step at a time. You decide how you learn; the
professor, TAs and these projects are resources along the way.

What we're hoping to grow in this unit:
1. Using agents to build real things.
2. Using and managing secrets (API keys, connection strings, tokens).
3. Learning, and getting better at learning, with confidence that carries into a career, whether that's
   interviews, a job or a startup.

## What gets handed in

Starting with the Podcast Recommender (for the Natural Language SQL project due Tue 10/13, you'll share a
report in Teams instead):

1. **The project**, in Canvas as before. This is **30%** of the project's points.
2. **A handwritten learning log** on paper. This is **70%** of the project's points.

The weighting reflects where the value is. With AI, a working artifact doesn't say much about what someone
learned; the learning is what you take with you.

## The learning log

One sheet of paper per project, front and back if you need it. Handwritten. It doesn't need to be pretty,
and it can read like an informal log rather than an essay. Paper will be available in class if you need some.

At the top: **your name, the project, and the date.** Then, for example:

- **Aha moments.** When something clicked, or when what you expected turned out differently.
- **Key concepts.** What *you* consider relevant and important to know, low level and high level, written
  so you could explain it to someone else.
- Anything else you find worth recording: questions you still have, how the agent helped or misled you.

**What you should have learned isn't spelled out.** Discovering that is part of the experience. If you're not
sure what matters, you could ask your agent to walk you through the important concepts behind what it
built, then decide for yourself what's worth writing down.

Why paper? Putting thoughts into your own handwriting asks you to distill them; there's something creative
about it. It's also a log the AI didn't write for you. If an agent helps you summarize, you're still the one
choosing what matters and transcribing it in your own hand (no printing or pasting).

## In class

Logs are due **in class on the next class day after the project is due**:

1. Bring your log.
2. Take a few minutes to share what you learned with a neighbor. Did you learn different things from the
   same project?
3. Pass the logs up to the front.

Professor Reynolds will write a log for each project too, and share it with the class.

**Missed class?** Drop your log at Professor Reynolds' office, **TMCB 2260**, the same day (under the door
or on the desk).

**Grace days** follow the project submission in Canvas, as usual. The log isn't tracked for grace days; the
expectation is that it comes along at about the same time as the project.
